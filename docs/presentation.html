Project Overview & Objectives

Requirements

Core Goal

Build an AI-powered processing pipeline that ingests business documents, maintains layout hierarchies during extraction, and maps content to structured JSON schemas.

Must dynamically route files using an intelligent agent classifier.

Key Architecture Rules

  • OCR Exclusions: Do not use Tesseract, PaddleOCR, or Surya OCR as primary solutions.
  • Layout Preservation: Must reconstruct tables, paragraphs, and reading orders.
  • FastAPI Wrapper: Dockerized REST service with schema overrides.

System Architecture & Agent Flow

Architecture

Agent Decision Nodes

  • Node 1: Digital vs. Scanned: Identifies if PDF has selectable vector text. Routes digital PDFs directly to PyMuPDF (bypass mode, 0ms OCR cost).
  • Node 2: Skew Correction: OpenCV checks skew angle and applies horizontal affine rotation before sending to OCR.
  • Node 3: Confidence Router: Executes Mindee docTR. If average word confidence is < 60%, falls back to EasyOCR.
Intelligent Pipeline Workflow
[Upload] ➔ [Classifier] ➔ [PyMuPDF / docTR / EasyOCR] ➔ [Gemini Structured Schema] ➔ [JSON]

Image Preprocessing & Skew Correction

Preprocessing

The Skew Correction Agent

Scanned documents are often tilted, causing letters to shift columns. Our preprocessor rectifies this in five steps:

  • 1. Convert to Grayscale
  • 2. Smooth with Gaussian Blur
  • 3. Threshold using Otsu binarization
  • 4. Dilate text blocks horizontally to create solid lines
  • 5. Detect lines & rotate image with warpAffine matrix

Key Benefits

  • Significantly improves OCR word recognition accuracy (reduces character spelling errors).
  • Prevents multi-column layout overlap during coordinate formatting.
  • Operates in sub-100ms using optimized OpenCV bindings.

Agent-Based Routing Selection

Routing Logic

Decision Routing Criteria

Instead of relying on a single engine, the agent routes documents based on layout properties:

  • Native PDF Bypass: High speed extraction using PyMuPDF. Completely avoids neural network overhead for electronic invoices.
  • Standard Business Forms: Dispatched to Mindee docTR to capture document hierarchy and coordinates.
  • Low Confidence Fallback: Dispatched to EasyOCR if docTR yields confidence < 60% due to background noise.

Performance Impact

Latency Optimization: Bypassing OCR for digital PDFs results in a 98% speedup (from 4.5 seconds to 0.05 seconds).

Accuracy Safeguards: Dual-model configuration ensures text recovery even in poor lighting or scanning conditions.

Problems Faced & Engineering Solutions

Challenges

Challenges Faced

  • CPU/RAM Heavyweight: PyTorch & Mindee docTR models take up ~800MB disk space, causing API startup lag.
  • Environment Incompatibility: Running CUDA-based models on standard local Windows CPUs without GPUs can cause crash states.
  • Noisy OCR Scans: Distortions in receipt printouts confuse coordinate layouts.

Solutions Implemented

  • Lazy Model Loading: Models load during runtime, reducing startup latency.
  • Mock Fallback Modes: Automatically triggers heuristic mocks if libraries fail to compile, guaranteeing 100% uptime.
  • Orientation Dilation: Image deskewing straightens lines, stabilizing OCR word bounding boxes.
